# Security Policy

## Supported versions

No production implementation has been released. Security support begins with the first approved release and follows the release notes for supported versions.

## Reporting a vulnerability

Do not open a public issue. Use GitHub’s private vulnerability reporting for this repository to submit impact, affected surface, reproduction details and any suggested mitigation. Do not access data that is not yours, degrade service, run denial-of-service tests, or retain/exfiltrate personal data while researching.

The project will acknowledge a valid report through the private advisory, triage severity, coordinate remediation/disclosure and credit the reporter when requested and appropriate. Response targets become operational before the first production release.

The normative security, privacy, threat and incident requirements are in [docs/quality/SECURITY_PRIVACY.md](docs/quality/SECURITY_PRIVACY.md).
